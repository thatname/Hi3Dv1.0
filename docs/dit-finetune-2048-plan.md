# DiT 2048³ 微调方案（草案）

更新日期：2026-11-07。状态：**方案草案，未实现训练代码，未做完整训练步**。本文对应 [v0.3 方案](experiment-plan-v0.3.md) 的 G4（接回 Hi3D 图片生成）及其“旧 DiT 兼容/生成器微调”里程碑；首轮 VAE 训练（G1–G3）的范围与结论不受本文影响。

验证类型标注：**[实测]** = 本机 GPU 实测；**[推算]** = 由实测外推、未运行；**[源码]** = 源码核查；**[待定]** = 尚需用户决定。

## 1. 目标与范围

- 用 2048³ 样本微调 Hi3D 发布的稀疏 flow DiT（`transformer_1024` 配置，256³ latent，patch 2 后 128³ token 网格）。
- 输入：预先编码好的 256³ latent（32 通道）与图片条件特征；训练循环内**不运行** VAE encoder/decoder 与图像编码器。
- 硬件目标：EPYC 服务器 + 若干 RTX 5080 16 GB（用户可负担的卡型）。4090/3090 工作站只用于测量与调试。
- 不在本文范围：VAE 训练、2048³ 目标生成、推理流式解码（流式 decoder 是 inference_mode 路径，不能当训练路径；多 GPU 流式推理不是 DDP）。

单个 block 反传峰值（相对基线的 allocated，4090，`experiments/dit_finetune/measure_train_block.py`）[实测]：

| token | 整块前向+反传 |
|---:|---:|
| 47,765 | 8.89 GiB |
| 66,601 | 12.39 GiB |
| 77,961 | 14.49 GiB |

约 0.19 MiB/token，线性。每块输出（一个 token×2112 fp16 张量）在 48k token 时 0.19 GiB。

结论：瓶颈是**激活**而非权重。一块权重 0.13 GiB，训练一块却需约 9 GiB。不做检查点的全反传约 190 GiB [推算]，任何单卡都放不下，所以检查点必须保留。

## 3. 关键技术：块内三段检查点

每个 block 顺序做三步（`sparc3d/nn/sparse/transformer/modulated.py:57-65`）：

1. 自注意力（token 之间）
2. 交叉注意力（token 看图片特征）
3. MLP（逐 token 两层网络）

整块检查点在反传时一次重算整块，三步的中间量同时驻留。三段检查点只保存每段输出，反传时按 MLP → 交叉注意力 → 自注意力逐段重算并反传，同一时刻只驻留一段的中间量。

15.5 GiB 上限（模拟无显示输出的 16 GB 卡，`experiments/dit_finetune/measure_16gb.py`）下单块峰值 [实测]：

| token | 整块 alloc / reserved | 三段 alloc / reserved |
|---:|---:|---:|
| 47,765 | 9.46 / 11.09 | 5.03 / 5.99 |
| 70,000 | 13.84 / 15.23 | 7.32 / 9.54 |
| 80,000 | 显存不足 | 8.35 / 10.15 |
| 120,000 | 未测 | 12.47 / 14.87 |
| 140,000 | 未测 | 显存不足 |

时间代价：与整块检查点相同，约多一次前向（预计每步慢 30–50%）；三段只额外增加少量小张量与 kernel 启动，未计时。实现时需与未拆分 block 比对梯度。

## 4. 单张 16 GB 卡的显存预算 [推算]

| 组成 | 48k token | 78k token |
|---|---:|---:|
| 当前段的激活与反传（三段） | 约 5.0 | 约 8.2 |
| 存储的块输出与检查点（约 10 个张量） | 1.9（GPU）或 0（放 CPU） | 3.1（GPU）或 0（放 CPU） |
| 输入路径（重算，仅留 skip 特征） | 约 0.3 | 约 0.5 |
| 当前块权重双缓冲 + I/O 权重 | 0.5 | 0.5 |
| 梯度暂存（2–8 个块，FP32） | 0.5–2.1 | 0.5–2.1 |

估算单卡上限：三段 + 存储张量在 GPU 约 70k token；三段 + 存储张量放 CPU 约 100k token。现用 300k 体素预算约 78k token，按后者可容纳。

未测部分：输出路径（上采样 + skip 拼接）的反传峰值、完整训练步、真实 5080 与 Linux 下的分配器碎片。4090 上推理 allocated 11.95 GiB 对应 nvidia-smi 17.13 GiB，碎片余量不可忽略。

## 5. 多卡与 CPU 侧

- **数据并行（DDP）**：每张卡训练自己的样本，N 张卡 ≈ N 倍吞吐、等效 batch N。单样本 token 上限不随卡数提高，因为全注意力要求一个 block 的整条序列在一张卡上。
- **权重与优化器放 CPU**：Adam 状态 13.4 GiB（8 B × 1.805B）放不进 16 GB 卡，必须在 CPU 上更新。主机内存预算约 22 GB（权重 + FP32 Adam），另加每卡存放检查点的空间。
- **MegaTrain 的作用**：其思路（CPU 存参数与 Adam、逐层流式进出 GPU、双缓冲、CPU 端 Adam）适合本场景，传输开销小（一块 0.13 GiB 约 10 ms PCIe，块计算 1–2 s）。但现仓库只支持 decoder-only LLM（`infinity/adapters/hf_decoder.py`）且训练循环接收 `input_ids`，不能直接运行 Hi3D 的稀疏坐标、共享调制、图片条件和 skip 连接。建议自行实现：PyTorch 检查点 + CPU Adam + 可选流式权重，只借鉴 MegaTrain 的设计。

## 6. 执行顺序与门槛

| 步骤 | 内容 | 通过条件 |
|---|---|---|
| D0 | 在 4090 上实现三段检查点，与未拆分 block 比对梯度 | 梯度相对误差在 fp16 容差内 |
| D1 | 4090 限制 15.5 GiB，跑最大样本的完整训练步（含输入/输出路径、loss、CPU Adam） | 不溢出；记录 alloc、reserved、nvidia-smi 与步时 |
| D2 | 单样本过拟合（固定 latent + 条件） | loss 稳定下降，无 NaN/溢出 |
| D3 | 购卡决策：对比 5080 16 GB 与二手 24 GB 卡的价格和 D1 余量 | 用户决定 |
| D4 | EPYC 上单卡 5080 复测 D1 | 结论与 4090 模拟一致 |
| D5 | 多卡 DDP 冒烟、恢复训练、NaN/显存监控 | 多卡梯度与单卡累积一致 |
| D6 | 正式微调与评测 | 指标见 [待定] 项 |

数据预处理：在 D2 前离线编码 latent；超过 token 上限的样本须在预处理阶段过滤或降低体素预算，训练中不得静默跳过或截断。

## 7. 风险

- **数值**：发布权重为 fp16，batch 1 下梯度易下溢；需要 loss scaling，或 BF16/FP32 主权重（FP32 主权重放 CPU 不影响显存）。
- **训练配方未公开**：Hi3D 原始训练方案未公开；时间步采样、loss 权重、条件丢弃比例都是假设，需单独对照。
- **latent 兼容**：若改用本工程新 VAE 的 latent，旧 DiT 不能按维度判断兼容（见 v0.3 §9），微调实际接近重新对齐，数据量与步数需求更大。
- **测量局限**：全部测量在 Windows 4090 上用合成球壳完成，测试时 GPU 上有其他进程在运行（影响速度，不影响 allocated 显存）；未用真实 5080。
