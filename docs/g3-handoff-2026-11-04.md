## 4. 运行时架构（本轮定型的部分）

- **编排器** `run_g3_stream.py`：A1/A2 生产者池 + A4 消费者池，按资产解耦（不是按组）。
- **生产者** `run_g3_producer_worker.py`：`O_EXCL` 抢 `claims/{index}.claim`（文件内容记 `{pid, started, index}`），一次一件，进程内循环。
- **消费者** `run_g3_a4_batch.py`：只取"A1/A2 已完成且无 A4 产物"的资产，40 件一批，每件 spawn 一个 `run_four_route_asset`。
- **分片 → 卡**：按"当前在跑分片最少的卡"分配，上限 `--max-shards-per-gpu 2`（旧实现 `number % len(gpus)` 会漂成 5-1-1-2-2-1-1-1）。
- **看门狗** `watch_slow_assets.py`：claim 超 `--max-seconds 600`（单件中位 118–130 s）就 SIGTERM worker、写 `claims/NNNNN.defer`（生产者跳过）、记入 `deferred-assets.json`。
- **坏资产账本** `skipped-assets.json` + `--max-a4-failures 2`：同一资产失败 2 次后不再派发。
- **背压**：积压 > `--pending-gb 400` 或磁盘可用 < `--min-free-gb 150` → 写 `pause`（生产者退出，消费者继续吃积压）。
- **重启标准流程**（务必照做）：杀进程 → **`clean_stale_targets --apply --drop-results --min-age-minutes 0`** → 启动 → 起看门狗。跳过第二步会让被杀的在飞资产以 `FileExistsError` 永久失败（曾一次丢 43 件）。

### 当前实测量级（26 生产者 / 14 消费者，8×H20-143GB）
- 场 **12.6–13.0 件/分**，单件中位 118–130 s；A4 **9–12.3 件/分**，单件中位 57–60 s（GPU 段仅 12.8 s，其余是 import/读缓存/指标）。
- 整机 idle 约 18–21%（生产者被 open3d 的 128 线程池限住，加进程会互相抢）。
- A4 每件约 **10 s 是 python 启动 + import**（占 17%），是下一步"批内复用进程"的收益点。

## 6. 训练代码现状（`g1_model.py` / `train_g1.py` / `train_g1_ddp.py`）

- **结构**：`G1VAE(decoder, encoder_scale)`；编码器 `ENCODER_LADDER` E0–E4（宽度阶梯，`attention_shifts` 只在**最粗 1/8 层**堆 2 个 `WindowAttention`，细层全是 `Residual`）；latent 32；解码器 = Hi3D PTv3 主干 + 自建 40 通道连续头。
- **冻结范围**：目前**只冻 `decoder.backbone.conv_out`**，主干与 `cls_head` 可训（`trace.md` 里 `decoder_backbone` 梯度范数 0.076 与编码器 0.115 同量级，证明在训）。
- **support**：训练 teacher-forced（直接用 GT 下一层 cell），推理才用 `logits > threshold` 自预测；occupancy 用朴素 BCE（无 pos_weight），各层等权平均。
- **角点**：每个 cell 独立预测 8 个角点，共享角点靠 `weight = 1/count` 缩放梯度，**没有一致性约束**。
- **采样**：`LazyTargets.indices = sorted(...)`，`index_at(position) = indices[position % len]`，训练用 `pick(step % len)` —— **固定顺序，无 shuffle**（`seed` 参数收了但从未使用）。
- **优化**：单一 AdamW(lr=1e-4)，**无 warmup / scheduler / grad clip / AMP**；DDP 因 `logvar` 头无梯度必须 `find_unused_parameters=True`。

## 7. 目前面临的问题（按优先级）

### P1 — 训练口径未定（阻塞正式训练）
- **冻结粒度未定**：A) 冻结 decoder 主干 + `cls_head`，训编码器（新头保留与否待定）；B) 只冻主干；C) 全冻。推荐 A，但要先确认"原版 `conv_out` 的输出语义"与 `target.npz` 的 field/delta 定义对齐，否则冻结后编码器的输出喂进去语义不一致。
- **新头去留**：若目标是"接原版 decoder"，自建的 40 通道连续头不应存在；但原版 `conv_out` 只有 sign/distance 两路，与 A4 的 delta 语义是否等价需要单独核对。**这是当前最大的未知**。

### P2 — 没有可比基线
R128/R256 数字失效（§5）。需要：从 g3 的 val/test 抽固定小子集（如 30+30，按面数分层）→ 冻结 decoder 的 E0 基线 → E4；两臂同口径。

### P3 — 表示层缺陷（与解码器是否冻结无关）
- **支承 teacher-forced vs 推理自预测的 mismatch**：直接导致"预测支撑比真值窄一圈、零面被切断"（此前 26 件诊断：边界顶点落在支撑外缘的中位数 0.68）。建议给 occupancy BCE 加 pos_weight 或按层加权。
- **共享角点不一致**：可能表现为 cell 边界的裂纹（R256 边界边中位 74）。需要确认 flexicubes 提取时如何处理重复角点（取一个还是平均）。

### P4 — 训练配方
无 warmup、无梯度裁剪、全参数同一 lr（随机编码器 + 预训练 decoder）、无 shuffle（manifest 按 id 哈希排序，若与面数相关会系统性漂移）、batch=1。冻结 decoder 后 ②的问题缓解，但编码器侧仍需 warmup + clip。

### P5 — 不是 VAE
`beta=0`、latent 取 mean、`logvar` 无梯度。若这些 latent 后续要喂 diffusion，需要 KL 项或"冻结/慢学习 decoder"；若只做重建则无所谓，但**不能自称 VAE**。

### P6 — E4 可能过大
98.89 M ≈ decoder 规模；输入是目标支撑本身，属"给定支撑的压缩重建"（偏易但非恒等映射）；注意力只在最粗层。结论应由 E0 vs E4 对照给出，而不是先验假设。

### P7 — A4 产能利用率低
单件 57 s 里约 10 s 是进程启动 + import（17%），GPU 占空比只有 30–50%（卡上两个分片相位错开才有 90%+）。改进方向：批内复用进程（一个进程连续处理多件）。

### P8 — 未解决的小项
- A4 结构性失败 18 件（CUDA 700 / 法向不收敛），已确认与渲染分辨率无关。
- `evaluate_g1` 依赖 `raw_mesh.ply`，**在 train split 上评测会 FileNotFoundError**（压缩时删了），只能评 val/test。
- 8771 页面 `a1a2.running` 恒为 0（grep 的是 `run_initial_batch`，而现进程名是 `run_g3_producer_worker`）。
- 数据漏斗 `asset-funnel.json` 是 14:50 的快照，需要用 `summarize_g3_funnel` 重跑刷新。

## 10. 坑与约束（踩过的）

1. `pkill -f run_g3_...` 会杀掉自己的 ssh 命令行 → 用 `ps -eo pid,comm,args | awk '$2 ~ /^python/ && /run_xxx/ {print $1}' | xargs -r kill`。
2. 杀生产者后**必须**跑 `clean_stale_targets`，否则残目录让资产永久失败（曾丢 43 件）。清理前用 mtime >30 min 保护在飞件。
3. `run_initial_batch.py` 的 sha 被 `plan.json` 固定（`0908d48f…`），改它会让进行中的 output-root 报 "Existing batch plan differs"。
4. open3d 的 `cast_rays` **不认 `nthreads` 也不认 `OMP_*`**，一件大网格能吃掉 60+ 核 → 只能靠"看门狗延迟"绕开，不能用限核（限核会让正常件也变慢）。
5. `taskset -pc <pid>` 只改主线程，要逐 `/proc/<pid>/task/*` 设置。
6. A4 批处理**没有单件超时**，`a4_present()` 只看产物 → 失败件会被无限重派（已用账本 + `--max-a4-failures` 解决）。
7. 训练首步有 455 s 预热（cuDNN/cuBLAS/spconv），前 5–8 分钟慢属正常。
8. `--stream-resident 1` 每步重载一件，重载成本可忽略；`--asset-device cpu` 只是放主机内存，不是流式。
9. 远端仓库为 `R256`（`8fb1921`），与本地逐字节一致，只差两个本地专用查看器文件；`origin/R256` 已同步。
